📦 1. 运行时存储组织（第9章）

🎯比喻：编译完的程序跑起来，变量、常量总得有地方"住"。编译器就是房产分配员：谁住哪儿、住多大的房、搬进搬出的规矩，都是它定的。
📦 要为谁分房（课件原话）：编译程序的功能是把源程序翻译成等价的目标程序，故还应负责为源程序中的量分配运行时存储空间——包括用户定义的常量、变量，以及参与运算的寄存器等；本章主要讲如何为用户定义的量分配空间。

两大分配方案

🏠人话版：静态分配=老单位分房——编译时门牌就刻死，谁住哪间、住多大永远不变，简单但死板（所以不许递归：递归几次编译时根本不知道，没法提前刻牌）。动态分配=住酒店随到随住——运行时来一次开一间：函数调用用栈式（后开的先退房），malloc/new 用堆式（自由申请归还）。
方案时机适用
静态存储分配编译时确定每个量的地址须满足两个条件（缺一不可）：数据对象大小已知 + 不允许递归/动态结构（FORTRAN 时代）
动态存储分配运行时按需分配栈式（过程调用，PL/0、C 局部变量）与堆式（malloc/new 自由申请）

活动记录（Activation Record）

🏨人话版：活动记录就是过程开的一间旅馆房间——每调用一次开一间（房里放着这趟的参数、局部变量和"房卡"返回地址），退房即腾空（调用结束弹出，房间还给别人用）。递归=同一位客人在店里同时开着好几间房（f(3) 没退房 f(2) 又来开房），各间的被褥互不混用——所以每层递归的 n 互不干扰。

过程的一次执行 = 该过程的一个活动（每执行一次过程体就产生一个活动）。管理一次执行所需信息的连续存储块就叫活动记录——里面装着：返回地址、形式参数、局部变量、临时单元等过程/参数相关信息。

🧠 关键理解：过程每被调用一次，就在栈顶新压入一张活动记录；调用结束就弹出。所以递归调用会同时存在多张同名过程的活动记录（每次调用的参数、局部变量各占各的房）。

参数传递：传值 vs 传地址

📄人话版：传值=给复印件——把实参的值复印一份给形参，形参在复印件上随便涂，原件毫发无损；传地址=给原件——形参拿到的是实参的存放地址，动笔就是直接改原件，函数返回后你的变量已经被改了。想"通过函数改我的变量"就得给地址，只"借值一用"给复印件就够。
传值 call-by-value传地址 call-by-reference
传什么实参的值拷贝给形参实参的地址给形参
对实参的影响形参怎么改都不影响实参对形参的操作会影响实参

类似 C 语言：默认传值，指针/引用实现"传地址"的效果。

PL/0 的运行时组织

以过程为单位的栈式动态存储分配：设一个数据空间栈，每调用一次过程，就按该过程的说明在栈顶分配一块数据区；调用完毕释放；递归调用则按调用深度先后设置多个不同数据区。

🚀 2. 代码优化与目标代码生成（第10章）

优化的目标与原则

目标：提高目标程序质量——减少存储空间和运行时间。手段：等价变换（变换前后程序结果必须一样）。原则：优化可在编译任何阶段进行，但会延长编译时间，应有选择地进行（Debug/Release 之别）。目标代码生成是编译的最终目的，涉及具体机器；本章重点是与机器无关的优化。

基本块

🧱人话版：基本块=一段一口气跑到底、中间不打岔的代码：只能从第一句进（单入口）、从最后一句出（单出口），中间没有岔路口（跳进/跳出）。像高铁直达区间：一站上车、终点下车、中途不开门。切出这样的小块，优化才能一块一块放心地做。
基本块 = 顺序执行的程序段，只有一个入口语句、一个出口语句（进去只能从开头进，出来只能从结尾出）。
基于基本块可做各种局部优化。
课件两个例子：赋值语句序列 a:=20; b:=a+20; c:=a*b 是一个基本块；IF 语句序列 k:=1; if k≥10 then x:=x+1 else y:=y+1 中，k:=1 单独成块，then/else 分支各自成块。

✍️ 手算示范：4 行小代码划分基本块（逐行旁注）

行代码【旁注】为什么在这切
1k := 1程序第一句，天然是入口 → 从这里起一个新块

🎮 三大优化技术实验室（点一个看前后对比）

🗣️人话版：①合并常量——能在编译时算的（3.14*2）绝不留到运行时再算；②外提不变式——循环里每次都重算同一个值太亏，搬到循环外只算一次；③消减强度——乘法比加法"贵"，i*4 改成"在上一趟结果上 +4"。一句话：能提前算的提前算，能少算的少算，能用便宜运算就不用贵的——但结果必须一模一样（等价变换）。
