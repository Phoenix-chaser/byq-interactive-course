1. 8.1 符号表：编译器的"户口本" 🔥 考点

🗂️人话版：源程序里每个名字（变量、常量、过程、函数……）都是一位"住户"。符号表就是编译器的户口登记簿：谁家住哪（地址）、什么身份（类型/类别）、管多大片区（作用域），全记在上面。查户口=查类型错误，分房=按户口分地址——后面两大功能都靠它。

1.1 符号表的作用与设计因素（课件第 2 页）

  • 符号表作为编译系统的重要组成部分，贯穿于文法分析、检查和语义处理的编译全过程。
  • 在编译程序中，符号表用来存放源程序中出现的有关名字的属性信息，这些信息集中反映了名字的语义特征属性。
  • 符号表总体结构的设计和实现与下列因素有关（两条，简答常考）：
    • ① 源语言的复杂性（包括词法结构、语法结构的复杂性）；
    • ② 对于编译系统在时间效率和空间效率方面的要求。
    （人话：语言越复杂、对编译速度/内存要求越高，符号表结构就得越讲究——所以有后面 4 种实现结构之分。）
🖼️ 原页对照：P2（点开看课件原图）

1.2 各阶段怎么用符号表（课件第 3 页上半）

符号表中所登记的信息在编译不同阶段都要用到：

  • 在词法分析及语法分析过程中不断更新表中的信息；
  • 在语义分析之前已经创建符号表，语义分析阶段写入名字属性信息；
  • 从词法分析到代码生成的各阶段，都会从表中获取不同的属性信息。

（人话：户口本不是一次性建好的——认名字时先登记，语义分析时补全档案，后面每个阶段都来翻档案。）

1.3 符号表的三大功能（课件第 3 页下半，简答必背）

#功能课件原文要点
①收集符号属性标示符、常量、变量、过程、函数等的属性都往里登记
②作为上下文语义的合法性检查的依据课件例：a := b + c——a、b、c 的类型查表才知道能不能这样算、要不要转换
③作为目标代码生成阶段地址分配的依据课件注：看类型——类型决定占几个存储单元，地址才分得下去

1.4 符号表的组成（课件第 4 页）

符号表包括名字栏和信息栏（可有多列）：

  • 名字栏：也称主栏。主栏的内容称为关键字（key word）——按它来查这一行（所以符号名不能重名）。
  • 信息栏：包含许多子栏和标志位，用来记录相应名字的各种属性。
符号表一行 = 名字栏（主栏/关键字） ｜ 信息栏（多列：类型栏、作用域栏、…… ）

1.6 符号表的五类操作（课件第 6 页）

在整个编译期间，对于符号表的操作大致可归纳为五类：

  1. 查：对给定名字，查询名字是否已在表中；
  2. 插：往表中插入一个新的名字；
  3. 取：对给定名字，访问它的某些信息；
  4. 写：对给定名字，填写或更新它的某些信息；
  5. 删：删除一个或一组无用的项（如出了作用域的名字）。

（人话口诀：查、插、取、写、删——登记户口的全流程。）

2.3 静态语义检查的四种检查（课件第 10 页）

课件定位句（爱考填空）：静态语义检查是代码生成前程序合法性检查的最后阶段。

检查课件原意例子
控制流检查
(flow-of-control checks)		控制流语句必须使控制转移到合法的地方break 语句必须有合法的语句包围它（裸写 break、不在循环/switch 里就是非法转移）

2.4 常见的语义错误与检查方法（课件第 11 页，流程必背）

声明和使用相关的语义错误就两种：① 标识符没有声明（用了一个没登记的名字）；② 重复声明（同一有效范围内又登记一遍）。如何检查？——全靠查符号表：

场景动作判定
遇到新声明的标识符查符号表当前有效的所有标识符中有相同名字的 → 重复声明错误；否则 → 生成它的属性信息，保存到符号表中
遇到标识符的使用查符号表没有找到 → 该标识符没有声明；否则 → 得到该标识符的属性，进行进一步分析（类型检查等）
💡记忆钩子：声明时查重、使用时查有。两种错误、两个方向，都只靠"查符号表"这一个动作——这也回应了 1.3 的功能②"合法性检查的依据"。

3. 8.3 中间代码生成：先译成"世界语" 🔥 考点

🌍人话版：直接把中文译成 100 种方言太累——先译成一门中立的世界语，再从世界语转各方言就省事了。中间代码就是编译器的世界语：先把它从"某语言、某写法"翻译过来，优化也方便，再交给后端生成各机器的目标代码。

3.1 引入中间代码的优缺点（课件第 12 页，简答必背）

优点（两条）缺点
① 中间代码与机器无关，便于移植（换个目标机只需换后端）
② 对中间代码的优化比源、目标代码优化容易		多了一级翻译（多一道工序，多花编译时间）

4. 四元式精讲（含课件 inttoreal 例子）🔥 考点

4.1 四元式的一般形式

四元式是三地址码（TAC）的经典书写格式，每条形如：

( 算符 op ，左操作数 ARG1 ，右操作数 ARG2 ，结果 RESULT )
  • 操作数可以是变量名、常数，也可以是编译器临时变量 T1、T2…（每需要"存一步中间结果"就借一个）；
  • 一元运算（如取负、类型转换）只用一个操作数栏，另一栏留空；
  • 赋值 x := e 写作 (:=, e, -, x) 这类形式。

4.2 课件经典例：Z := X + 0.618 * Y（含语义分析的 inttoreal）

这是课件的招牌例子（第 1 章课件第 23 页原例，本页作补充精讲）：源语句 Z := X + 0.618 * Y，其中 0.618 是实型、Y 是整型。语义分析（类型检查）发现 mixed 运算，先插入一条类型转换指令 inttoreal 把 Y 转成实型，再翻译成四元式：

序号算符左操作数右操作数结果【旁注】
(1)inttorealY—T1语义分析插入的类型转换：整型 Y → 实型 T1
(2)*0.618T1T2先乘：0.618 × T1 → T2（临时变量登场）
(3)+XT2Z后加：X + T2 → 直接送 Z
📌 看点两个：① inttoreal 这条不是程序员写的，是语义分析（类型检查）替你加的——这是"语义分析发现类型不匹配→自动转换"的标准示范；② 四元式顺序体现先乘除后加减的优先级，中间结果交给临时变量 T1、T2 暂存。这个例子的语义树/语法树上标注的正是 inttoreal 插入的位置。

🎮 到第 5 关玩四元式生成器演示器：输入任意表达式，看它一步步翻成四元式（还有 Z := X + 0.618*Y 的逐条旁注手算版）。

4.3 补充小练：a + b * c 的四元式（先自己写再看）

(*) b c T1
(+) a T1 T2

两条：先算 b*c 借 T1，再 a+T1 得 T2。规律：运算每"分层"一次，就借一个临时变量；四元式条数 = 表达式的运算次数。

符号表贯穿全程：收集属性 / 合法性检查依据 / 地址分配依据；组成=名字栏(主栏=关键字)+信息栏；6 类常见属性、5 类操作（查插取写删）、4 种实现（线性-PL/0、有序-折半、栈、Hash）。静态语义分析=编译期检查（控制流/唯一性/名字相关/类型，是代码生成前最后一道合法性关口）+收集语义信息；未声明/重复声明全靠查符号表。中间代码：优（机器无关、易优化）大于缺（多一级翻译），五种形式（AST/TAC/P-code/Bytecode/SSA），主角是四元式（op, ARG1, ARG2, RESULT，inttoreal 例）。
