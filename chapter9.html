1. 9.1 运行时存储组织概述 🔥 考点

🏠人话版：编译完的程序跑起来，变量、常量总得有地方"住"。编译器就是房产分配员：谁住哪儿、住多大的房、搬进搬出按什么规矩，都是它定的——而且它要在编译时就把这套规矩（分配方案）安排好，运行时照章执行。

1.1 为什么要编译器来分房（课件原句逐句讲）

课件第 2 页原文，逐句拆：

  • ①"编译程序的功能是把源程序翻译成等价的目标程序，故编译程序还应负责对源程序中的量分配运行时的存储空间。"——翻译"等价"不仅指算出来的结果一样，还指运行时每个量都有处可放；分房是翻译工作的分内事。
  • ②"这些量包括：用户定义的常量、变量；参与运算的寄存器等。"——分配对象两类（选择题考列举）：用户定义的常量、变量 + 参与运算的寄存器等。
  • ③"本章主要介绍如何为用户定义的量分配存储空间。"——章节范围声明：重点是前者（常量、变量），寄存器分配只提及不展开。

1.2 两种存储组织和分配方案（课件原句 + 展开）

课件给出两大方案（一句带过条件，展开如下）：

方案课件原话展开讲（教材标准口径）人话版
静态存储分配方案需要满足两个条件，缺一不可① 每个数据对象的大小和所需的存储空间在编译时都能确定（不许有编译时定不下来长度的量）；② 不允许递归调用、不允许运行中动态生成数据对象（一个过程只有一份固定的数据区）老单位分房：编译时门牌刻死，永远不变——简单但死板
动态存储分配方案（栈式、堆式）栈式：随过程调用/返回在栈顶分配/释放（PL/0、C 局部变量）；堆式：随时申请、随时归还（malloc/new）住酒店：随到随住、走后退房（栈=叠罗汉式退房；堆=自由市场）
📌 考试抓手：静态方案那两个条件是课件特别强调"缺一不可"的地方——少一个就只能转动态。反过来说：递归/动态数据结构 ⇒ 必须动态分配（这是 9.4 PL/0 选栈式的根本原因）。

2. 9.2 活动记录 🔥 考点

2.1 两个定义（名词解释高频，逐句背）

定义一：什么是"活动"（课件原句）

一个过程的活动是指该过程的一次执行，即每执行一次过程体，就产生该过程的一个活动。

定义二：什么是"活动记录"（课件原句）

为了管理过程在一次执行中（即过程的活动）所需要的信息，使用一个连续的存储块表示该活动的相关信息，称之为该过程的活动记录（Activation Record）。

课件补一句：活动记录记录了过程/参数的相关信息。

🏨人话版：活动 = 过程"跑一趟"；活动记录 = 这一趟开的一间旅馆房间：房里放这趟要用的参数、局部变量、临时单元和"房卡"——返回地址（记着退房后回哪儿）。每调用一次开一间新房间，退房即腾空。注意定义里"一次执行"三个字：递归 3 次就有 3 个活动、3 张活动记录，各住各的房，互不串门。

2.2 活动记录示意图/结构（课件 P234 图9.4、P235 图9.6 文字化）

课件注明：活动记录示意图见教材 P234 图 9.4，活动记录结构见 P235 图 9.6。把典型结构自顶向下文字化（具体栏目以教材图为准，考试主要抓"装哪些类型的信息"）：

┌─────────────────────┐ ← 高地址
│ 实在参数（传给本过程的实参） │
│ 返回地址（退房后回哪儿）     │
│ 控制链/动态链（指向调用者的活动记录）│
│ 访问链/静态链（找外层过程的数据用，PL/0 用静态链）│
│ 保存的机器状态（寄存器现场等）│
│ 局部数据（本过程说明的变量、常量）│
│ 临时单元（中间计算结果）     │
└─────────────────────┘ ← 低地址（栈顶方向，下一个活动记录压在这下面）

要点三条：① 是一整块连续存储（"连续的存储块"）；② 内容 = 过程/参数相关信息（参数、返回地址、链、局部量、临时单元）；③ 它随过程调用而建立、随返回而撤销——天然按栈的方式摞起来。

3. 9.3 过程调用：传值 vs 传地址 🔥 考点

3.1 课件原句 + 对比表

  • 传值（call-by-value）：对形参的操作不影响实参。
  • 传地址（call-by-reference）：对形参的操作会影响实参。
  • 课件注：类似于 C 语言中函数参数的传递方式（C 默认传值；传指针/引用可实现传地址的效果）。
对比项传值 call-by-value传地址 call-by-reference
传给形参的是什么实参的值（拷贝一份）实参的地址
对形参的操作只动"复印件"，不影响实参直接写"原件"，会影响实参
函数能否改外面的变量不能能
C 语言对应默认方式 f(a)指针 f(&a)（C 即可）；引用 f(a) 声明 void f(int &a)（仅 C++）

3.2 经典例子：同一个 swap，两种命运

procedure swap(x, y: integer);     { 一模一样的过程体 }
var t: integer;
begin
  t := x; x := y; y := t          { 三步交换 }
end;

{ 调用 }  swap(a, b)   { 设 a=3, b=5 }
调用方式过程内发生了什么返回后 a, b
传值x、y 拿到的是 3、5 的复印件，交换只发生在复印件上a=3, b=5（没变！）
传地址x、y 拿到的是 a、b 的地址，t:=x 读 a，x:=y 写 b，y:=t 写 a——步步都落在原件上a=5, b=3（真的换了）
📌 判断口诀：函数里改了形参，出来实参没变→传值；变了→传地址。"想借值一用，给复印件就够；想让人替你改，必须给原件（地址）。"

C 语言对照（课件"类似于 C 语言中函数参数的传递方式"）：

void f_val(int x) { x = x + 1; }   // 传值：改的是复印件，外面的 a 不变
void f_ref(int *x) { *x = *x + 1; } // 传地址：拿到 a 的地址，改的就是 a 本身
f_val(a);  // 调用后 a 不变
f_ref(&a); // 调用后 a 真的 +1

4. 9.4 PL/0 编译程序的运行时组织 🔥 考点

4.1 基本思想全文（课件一字不落）+ 逐句精讲

基本思想：以过程为单位的栈式动态存储分配。所谓以过程为单位进行分配就是以过程调用为单位来设置数据区，即设置一个数据空间栈，当程序运行时，每调用某过程一次，就根据该过程的说明为该过程在数据区的顶部分配一定数量的存储单元作为该过程的数据区，当调用完毕，则释放该过程的数据区。若是递归调用，则根据调用深度分别为各次调用而先后设置不同的数据区。

整段拆成 5 个要点（简答就按这 5 点写）：

#原句关键词【旁注】讲透
①以过程为单位（以过程调用为单位来设置数据区）分配的基本单位不是"变量"而是"过程的一次调用"：调一次、开一区
②设置一个数据空间栈整个运行空间组织成一个栈；栈底通常是主程序数据区
③每调用一次，根据该过程的说明在数据区顶部分配一定数量的存储单元"根据该过程的说明"=按过程中说明的常量/变量个数算出要多大（这些在编译时就已知，PL/0 代码生成时就算好单元数）；"顶部"=栈顶；"一定数量"=不是无限，是说明定好的大小
④调用完毕，释放该过程的数据区后调用的先释放——后进先出，所以用栈；腾出的空间可给后续调用复用
⑤递归调用：按调用深度分别为各次调用先后设置不同的数据区同一过程被自己调用多次 → 多个数据区并存，一层一个，按调用深度先后压入；每层的参数/中间结果互不干扰——这就是 PL/0 支持递归的存储基础（静态分配一份空间就做不到）
🧳人话版：数据空间栈是一摞行李箱：每调用一个过程，就把"按它的说明定制"的箱子摞在最上面；它一返回，最上面那个箱子先搬走。递归就是同款箱子摞了好几层——每层装的都是当次调用的参数和局部量，所以 f(3) 没算完时 f(2) 的 n=2 绝不会被 f(3) 的 n=3 冲掉。

4.2 P244-245 举例的原理说明（"讲解具体过程"文字化）

课件第 5 页指向教材 P244-245 的例子并"讲解具体过程"。其原理用调用时间线文字化（以 主程序 M → 调用过程 A → A 内调用 B → B 返回 → A 返回 为例；若 A 递归则同理多摞几层）：

时刻  事件                 数据空间栈（左=栈底，右=栈顶）
 1    程序启动             [ M ]
 2    M 调用 A             [ M , A ]          ← 按过程 A 的说明在顶部压入 A 的数据区
 3    A 内调用 B           [ M , A , B ]      ← B 压在 A 上面（B 能通过静态链找到 A、M 的量）
 4    B 执行完返回         [ M , A ]          ← 调用完毕：释放栈顶 B 的数据区
 5    A 执行完返回         [ M ]              ← 释放 A；若 A 是递归调用自己，
                                               每深入一层就再压一个 A 的数据区，
                                               按调用深度先后设置、逐层退栈

三个看点：① 分区的依据——"根据该过程的说明"（编译时即知每个过程的量要占多少单元）；② 静态链/控制链把各层数据区串起来，里层过程能引用外层过程的量（PL/0 的三层函数嵌套就靠它）；③ 递归多数据区——同一过程名，栈里可以同时有几份，按调用深度区分。这也解释了 9.1 的结论：PL/0 允许递归，所以必须采用动态（栈式）分配，静态方案那份"唯一数据区"装不下递归。

🎮 想亲眼看递归怎么"一层层压栈、再一层层退栈"？到第 6 关玩活动记录栈动画演示器（调用 P(3) 单步执行，与上面时间线完全对应）。

4.3 本章三组易混概念辨析（考前过一遍）

易混对一句话分清
活动 vs 活动记录活动是过程的一次执行（动态的事）；活动记录是为这次执行管理信息的连续存储块（静态的物）。一次活动对应一张活动记录。
活动记录 vs 数据区（PL/0）PL/0 课件里说"数据区"——以过程为单位分配的那块存储单元，概念上与活动记录同一位置：一次调用一份，栈顶摞放。
静态分配 vs 动态分配编译时定死 vs 运行时按调用分配；能否递归是分水岭（要递归就必须动态）。
栈式 vs 堆式栈式随过程调用"后进先出"整体分配/释放；堆式随时申请随时归还（malloc/new），次序自由。

4.4 本章常考问法（按课件原句作答）

  • 问：编译程序为什么要负责存储分配？答：编译程序的功能是把源程序翻译成等价的目标程序，故还应负责对源程序中的量（用户定义的常量、变量；参与运算的寄存器等）分配运行时的存储空间。
  • 问：静态存储分配需要满足什么条件？答：需要满足两个条件，缺一不可（大小/位置编译时可确定 + 不允许递归等动态情况）。
  • 问：什么是活动？什么是活动记录？答：见 2.1 两个定义，逐句背。
  • 问：传值与传地址的区别？答：传值不影响实参，传地址会影响实参（类似 C 语言函数参数传递）。
  • 问：简述 PL/0 运行时组织的基本思想。答：背 4.1 那段全文（以过程为单位的栈式动态存储分配 + 5 个要点）。

📖 本章一句话小结

编译程序还要负责为源程序中的量（用户定义的常量、变量 + 参与运算的寄存器等）分配运行时存储空间；两种方案——静态（两条件缺一不可：大小编译时可定 + 不允许递归）与动态（栈式/堆式）。活动=过程的一次执行；活动记录=管理一次执行所需信息的连续存储块（参数、返回地址、链、局部量）。参数传递：传值不影响实参、传地址会影响（类似 C）。PL/0：以过程为单位的栈式动态存储分配——数据空间栈、调用即压栈顶、完毕即释放、递归按深度多数据区并存。
