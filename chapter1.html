0.5 课程简介：课程学习的意义——为什么要学编译？（课件第 9~10 页）

🗣️人话版：这辈子你多半不会亲手写一个 C++ 编译器，但你一定会遇到"要用编译技术"的项目——配置文件解析、公式引擎、SQL 分析、代码高亮……全是编译的活。课件甚至说：编译器也许是你在本科阶段分析得最透彻的一个实例。

课件大意（很适合用来回答"学编译有什么用"）：从软件工程看，编译器是一个很好的实例，所介绍的概念和技术能应用到一般的软件设计之中。可以说，我们其中大部分人在一辈子的生涯中都没有机会去实现一个真正的复杂语言的编译器，但是每一个人都绝对会遇到需要使用编译技术的项目。

💡 课件举的两个"小编译器"例子：普通计算器和可编程计算器——输入一个表达式，它们同样要经历"认符号 → 查对错 → 按规则算出结果"这套流程，本质上就是两个小型"翻译程序"。

起点问题：高级语言程序如何在计算机上执行？（课件第 13 页）

你写的 C / Java，CPU 并不直接认识（它只认机器语言）。于是只有两条路：

路线做法靠谁
先编译后执行把高级语言程序翻译成机器语言程序，再运行所得机器语言程序求得计算结果编译程序
解释执行边解释、边执行解释程序
🎯比喻：拿到一整本厚厚的中文书要给英国读者看——编译像请笔译家把整本书从头到尾译完、装订成英文版再交付，读者读起来飞快；解释像请口译坐旁边，英国人读一句、口译翻一句，不用等整本译完就能开始，但每读一句都要等翻译。

🔥【考点】三个定义：翻译程序 → 编译程序 / 解释程序（课件第 14~16 页）

三个定义是一层套一层的：翻译程序是大圈子，编译程序和解释程序是里面两个小圈子。

  • 翻译程序 / 翻译器（Translator）：它读入用某种语言编写的程序（源程序 Source Program），并翻译成一个与之等价的、用另一种语言编写的程序（目标程序 Object Program）。这两种语言分别称为源语言和目标语言。
  • 编译程序 / 编译器（Compiler）：就是一种语言翻译程序，只不过它的源语言是高级语言（C、Java、Pascal），目标语言是低级语言（汇编语言、机器语言）。
  • 解释程序 / 解释器（Interpreter）：它以该语言写的源程序作为输入，但不产生目标程序，而是边解释、边执行源程序本身（典型：Shell、JavaScript、SQL）。
源程序（*.C / *.java）──► 翻译程序 ──► 目标程序（*.OBJ / *.EXE）
解释路线：源程序（Shell / JavaScript / SQL）＋ 输入数据 ──► 解释程序 ──► 计算结果（没有目标程序这一站）
📌 答名词解释题的模板：翻译程序答"源程序→等价的目标程序"两个关键词；编译程序再加上"高级→低级"；解释程序强调"不产生目标程序、边解释边执行"。阅卷老师踩点给分。

🔥【考点】编译程序和解释程序的区别（课件第 17 页）

🗣️先说人话：两者的本质区别只有一句话——是否生成目标代码。剩下所有差别（错误发现时机、执行效率）都是这一句话衍生出来的：整本译完再读（编译），错误当然在"译"的时候就被抓出来；读一句翻一句（解释），错误只能拖到"执行到那一句"才暴露。

课件原文给的思考题："程序的编译与解释有什么区别？"完整解答如下：

  • 本质区别：二者本质区别在于是否生成目标代码（编译生成，解释不生成）。类比：笔译与口译。
  • 代表语言：编译型代表 C&C++、C#、Java；解释型代表 Shell、JavaScript、SQL。
  • 错误发现时机：编译型语言的源代码有错误则编译不通过，无法生成可执行代码，更无法执行程序；解释型语言只有执行时才会判断是否出错，即使一句出错，也可以继续执行下一句。
  • 执行效率：编译型语言执行效率上大大优于解释型（目标代码已整体生成，执行时不再反复翻译）。
对比项编译型（C&C++、C#、Java）解释型（Shell、JavaScript、SQL）
是否生成目标代码生成不生成
执行方式先编译后执行边解释边执行
错误发现时机编译时发现，编译不通过则无法执行执行到才判断，一句出错可继续下一句
执行效率大大优于解释型较低

🔎 1.2.1 编译过程概述：六个阶段逐个拆（课件第 20~27 页）

阶段① 词法分析——"查词典的人"（课件第 20 页）🔥【考点】

  • 又称扫描器（Scanner）：任务是把源程序变换成单词符号序列。
  • 单词符号分为 5 类：基本字（关键字/保留字）、标识符、常数、算符和界符。
  • 词法规则用正规式和有限自动机描述（第 3 章展开）。

课件例子 1（英文侧）：循环语句 for I := 1 to 100 do 被切成 7 个单词：

源代码片断forI:=1to100do
单词类别基本字标识符（id）赋值号整常数基本字整常数基本字

于是这行源代码变成了单词符号流：基本字for｜标识符id｜赋值号:=｜整常数1｜基本字to｜整常数100｜基本字do，源源不断送入下一阶段。

注意 I：所有标识符统一归成 id 这一类，具体是哪个"I"靠属性区分——词法分析器同时把 I 登记进符号表（课件图中 I 登记在第 1 项），以后出现"id"就带着指向符号表表项的指针。

课件例子 2（中文对照侧）：句子"你们是优秀的燕大学子。"经"查词典"后：名词（你们）、动词（是）、形容词（优秀的）、名词（燕大学子）——得到词类序列 名词1 动词 形容词 名词2。查词过程同样要翻词典（课件图中查到的词按 1、2、3 逐条登记），遇到不认识的词要记出错记录。

阶段② 语法分析——"组词成句的人"（课件第 21 页）🔥【考点】

  • 任务：在单词符号串上组建语法单位，并最终判断输入串是否构成语法上正确的"程序"。
  • 语法单位：短语、句柄、句子、程序段和程序。
  • 语法规则用上下文无关文法描述，涉及分析树（第 4、5、6 章展开）。

课件例子 1（代码侧）：赋值语句 Z := X + 0.618*Y，词法分析后成为 id1 := id2 + 0.618 * id3，语法分析给它建出语法树：

Z := X + 0.618*Y
        :=
       /   \
      Z     +
           / \
          X   *
             / \
         0.618  Y        ← 叶子从左到右读回来，正好是原句：树 = 句子的"成分结构图"

课件例子 2（中文对照侧）："你们是优秀的燕大学子"同样被建出一棵结构树（课件图文字版）：

              语句
        ┌──────┼──────────┐
      主语     谓语       宾语
        │       │       ┌──┴──┐
       名词    动词    定语   名词
        │       │       │      │
      (你们)   (是)  (优秀的)(燕大学子)

主语＋谓语＋宾语齐了、搭配合法 → 语法正确；定语"优秀的"挂在宾语头上。代码侧的"主谓宾"就是 赋值语句 = 标识符 := 表达式 这样的语法单位。

阶段③ 语义分析——"讲不通就要打回的人"（课件第 22 页）🔥【考点】

  • 任务：按照语义规则，对语法分析器归约出的语法单位进行语义分析，并把它们翻译成一定形式的中间代码。
  • 语义检查两件事：变量是否定义、类型是否正确（第 7、8 章部分内容展开）。

课件例子 1（中文对照侧）："你们是优秀的燕大学子"✔ 语法对、语义也通；"你们是一个优秀的燕大学子。"✘ 语法完全合法（主谓宾俱全），但"你们"是复数、"一个"是单数，语义上数量不一致——这正是语义分析要抓的错误：句子合法 ≠ 句子讲得通。

课件例子 2（代码侧，类型检查经典图）：还是 Z := X + 0.618*Y。0.618 是实型数，参与运算的另一个操作数若还是整型，类型就不匹配——语义分析在语法树上插入 inttoreal 转换节点（整型 → 实型），把整型操作数先转成实型再相乘：

语义分析前的树：            语义分析后的树（插入 inttoreal）：

        :=                        :=
       /   \                     /   \
      Z     +                   Z     +
           / \                       / \
          X   *                     X   *
             / \                       /    \
         0.618  Y               0.618   inttoreal
                                            |
                                            Y   ← Y 前多了一站"整转实"

阶段④ 中间代码生成——"先打草稿"（课件第 23 页）🔥【考点】

  • 任务：把源程序的记号流翻译成一定形式的中间代码；这种中间语言程序是某种抽象的程序（不绑定具体机器）。
  • 本课采用的中间代码形式：四元式（第 8 章展开）。

课件例子（中文对照侧）：翻译家把"你们是优秀的燕大学子"落成英文草稿 You are good YsuUers.——定语"优秀的"变成表语 good，按英文习惯重新组织，这一步对应"英文文本生成"。

课件例子（四元式表）：Z := X + 0.618*Y（Y 已由语义分析标注需转实型）翻译成三条四元式，每条形如（算符，左操作数，右操作数，结果）：

(1)inttorealY－T1先把整型 Y 转成实型，放进临时变量 T1
(2)*0.618T1T20.618 × T1 → T2
(3)+XT2ZX + T2 → Z，一条赋值语句拆成三步算
🧠为什么中间要打"草稿"（中间代码）而不直接翻成机器码？草稿（中间代码）与机器无关、结构规整，往后既能方便地做优化，也方便换目标机——这正是 1.2.3 前端/后端能拆开的前提。

🔥【考点】分析 与 综合（课件第 24、26 页）

课件用两张大图强调同一个结论，六个阶段按职责一分为二：

包含阶段在干什么
前四个阶段词法分析、语法分析、语义分析、中间代码生成完成对源程序的分析（拆开、看懂它）
后两个阶段代码优化、目标代码生成完成对源程序的综合（组装、产出它）
🎯记法：像拆快递和装快递——前四步把源程序"拆开验货"（分析），后两步按订单"重新打包发货"（综合）。考试爱考"下列哪个阶段属于综合"，答案只会落在优化、目标代码生成里。

阶段⑤ 代码优化 ＋ 阶段⑥ 目标代码生成（课件第 25 页）

  • 代码优化：对中间代码进行优化处理（第 10 章展开）。身边最熟悉的例子：Debug 版 / Release 版——同一份程序，Release 版编译时优化更狠，跑得更快、体积更小。
  • 目标代码生成：把中间代码翻译成目标程序（汇编 / 机器语言），是编译的最后一步，涉及具体机器（第 10 章展开）。

🔥【考点】表格管理 与 出错处理：两根"电线"（课件第 28 页）

  • 表格管理（符号表管理）：用来登记源程序中出现的每个名字及其属性，如常量名、变量名、过程名等；如果是变量名，其属性有类型、内存大小、地址等（第 8 章部分内容展开；第 9 章还会讲编译阶段如何为源程序中的量分配存储空间）。
  • 出错处理：用来发现程序中的错误（课件注明无专门章节，散落在各阶段讲）。程序中的错误分为语法错误和语义错误两类，发现时机不同：
错误类型典型例子在哪个阶段被抓到
语法错误非法字符词法分析阶段
括号不匹配语法分析阶段
语义错误类型错误语义分析阶段
🎯记法：表格管理和出错处理像教室里的两根电线——讲台（六阶段）走到哪，它们就供电到哪；不是某个阶段专属，而是贯穿编译全过程。判断题里"出错处理只在语法分析进行"这类说法一律错。

🔀 1.2.3 编译阶段的组合：前端 / 后端 与 遍（课件第 30~32 页）

🔥【考点】编译前端 与 编译后端（课件第 30 页）

  • 编译前端：与源语言有关，与目标机无关——包含词法分析器、语法分析器、语义分析器、中间代码生成器。
  • 编译后端：与源语言无关，与目标机有关，依赖于中间代码——包含代码优化、目标代码生成。
🗣️人话版：前端只管"看懂稿子"——稿子是中文、英文还是日文（源语言）决定前端怎么写，至于译出来给谁看（目标机）它不管；后端只管"按读者的口味排版出货"。中间代码是两家交接的标准接口，所以后端"依赖于中间代码"。

两种经典组装方式（课件第 31 页）

组合一：前端相同，后端不同 —— 同一语言跑上不同机器（如 X86 / X64）

              ┌── 后端1 ──► 目标机器1（X86）
源语言 ──► 前端 ├── 后端2 ──► 目标机器2（X64）
              ├── 后端3 ──► 目标机器3
              └── 后端n ──► 目标机器n

组合二：前端不同，后端相同 —— 不同语言编译成相同的中间语言

源语言1 ──► 前端1 ──┐
源语言2 ──► 前端2 ──┤
源语言3 ──► 前端3 ──┼──► 后端 ──► 目标机器
源语言n ──► 前端n ──┘

课件原话：前端相同、后端不同，以便在不同的目标机器上运行相同的语言（X86/X64）；前端不同、后端相同，将不同的语言编译成相同的中间语言。这就是"一次写前端、到处配后端"的工程红利。

🔥【考点】遍（趟，pass）（课件第 32 页）

编译程序通常被组成若干遍。所谓遍（趟），就是对源程序或源程序的中间结果从头到尾扫描一次，并作有关的加工处理，生成新的中间结果或目标程序。
  • 课件注释 1：PL/0 是单遍扫描的编译程序（一趟走完，边扫描边完成各阶段工作）。
  • 课件注释 2：具体采用几遍扫描与多种因素有关，由设计者综合考虑决定（不是越多越好，也不是必须几遍）。
🎯比喻：遍数就像收拾房间的"趟数"——高手一趟从头到尾边走边收（单遍，省时间但要记性好），新手先扫一遍收衣服、再扫一遍收书（多遍，每趟只干一件事，内存压力小）。所以遍数是时空与复杂度的权衡，由设计者拍板。

🧰 1.3 解释程序和一些软件工具（课件第 33~34 页）

编译程序的小伙伴：程序设计环境（课件第 33 页）

  • 解释程序前面已讲过（见 1.1），课件戏称它是"编译程序的小伙伴"。
  • 课件论断：编译程序无疑是实现高级语言的一个最重要的工具，但支持程序员进行程序开发通常还需要一些其它工具——如编辑程序、连接程序、调试程序等等。
  • 编译程序与这些程序设计工具一起，构成所谓的程序设计环境。

集成开发环境 IDE（课件第 34 页）

  • 早期问题：在高级语言发展的早期，这些程序设计工具往往是独立的，缺乏整体性，而且也缺乏对软件开发全生命周期的支持。
  • 趋势：随着软件技术不断发展，人们越来越倾向于构造集成化的软件开发环境——IDE（Integrated Development Environment）。
  • 集成化环境的特点：将相互独立的程序设计工具集成起来，为程序员提供完整的、一体化的支持，从而进一步提高程序开发效率、改善程序质量。
🗣️人话版：早年写代码要"编辑器存盘 → 命令行编译 → 链接器连接 → 调试器另开窗口"，工具各管一段；IDE 就是把这些小伙伴拉进同一间办公室（你现在用的 VS Code / Dev-C++ / IDEA 就是），一个按钮背后整条流水线联动。

思考题（课件第 17 页原题）：程序的编译与解释有什么区别？

✅ 完整解答：①本质区别在于是否生成目标代码——编译生成目标程序，解释不产生目标程序、边解释边执行源程序本身（类比笔译与口译）；②代表语言：编译型如 C&C++、C#、Java，解释型如 Shell、JavaScript、SQL；③错误发现时机不同：编译型源代码有错误则编译不通过，无法生成可执行代码；解释型执行时才判断是否出错，一句出错仍可继续执行下一句；④效率不同：编译型执行效率大大优于解释型。

自测 1：什么是翻译程序？什么是编译程序？什么是解释程序？

✅ 解答：翻译程序读入用某种语言编写的程序（源程序），翻译成与之等价的、用另一种语言编写的程序（目标程序），两种语言分别称源语言和目标语言。编译程序是源语言为高级语言（C、Java、Pascal）、目标语言为低级语言（汇编语言、机器语言）的翻译程序。解释程序以源程序为输入，但不产生目标程序，而是边解释、边执行源程序本身。

自测 2：编译过程分哪几个阶段？各阶段的任务一句话是什么？

✅ 解答：六个阶段。①词法分析（扫描器）：源程序 → 单词符号（基本字、标识符、常数、算符、界符五类）；②语法分析：单词串 → 语法单位（短语、句柄、句子、程序段、程序），判断是否构成语法上正确的程序；③语义分析：按语义规则检查（变量是否定义、类型是否正确），可插 inttoreal 之类转换；④中间代码生成：记号流 → 四元式等中间代码；⑤代码优化：对中间代码做优化处理；⑥目标代码生成：中间代码 → 目标程序。前四个阶段完成对源程序的分析，后两个阶段完成综合；表格管理与出错处理贯穿全程。

自测 3：什么是"遍"？PL/0 编译程序是几遍的？遍数由什么决定？

✅ 解答：遍（趟，pass）就是对源程序或源程序的中间结果从头到尾扫描一次，并作有关的加工处理，生成新的中间结果或目标程序。PL/0 为单遍扫描的编译程序。具体采用几遍扫描与多种因素有关，由设计者综合考虑决定。

自测 4：什么是编译前端和编译后端？两种组合方式各解决什么问题？

✅ 解答：编译前端与源语言有关、与目标机无关（词法、语法、语义分析、中间代码生成）；编译后端与源语言无关、与目标机有关、依赖于中间代码（代码优化、目标代码生成）。前端相同、后端不同，可在不同目标机器上运行相同的语言（X86/X64）；前端不同、后端相同，可将不同的语言编译成相同的中间语言。

自测 5：典型编译程序由哪 8 个程序组成？表格管理和出错处理各做什么？

✅ 解答：词法分析程序、语法分析程序、语义分析程序、中间代码生成程序、代码优化程序、目标代码生成程序、表格管理程序、出错处理程序，8 个框各对应一个程序，有机组合形成典型编译程序。表格管理（符号表管理）登记源程序中每个名字及其属性（变量名有类型、内存大小、地址等）；出错处理发现程序错误——语法错误在词法分析（非法字符）和语法分析（括号不匹配）时检测，语义错误（类型错误）在语义分析时检测。
