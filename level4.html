🧗 1. 自底向上：从句子爬回树根

🎯比喻：自顶向下是"看菜谱做菜"（从 S 推导到句子）；自底向上是拼图逆推——手里拿着成品（输入串），不断把符合规则的小块（句柄）还原成大块（非终结符），最后如果能拼回开始符号 S，就说明它是合法句子。这个"每次归约当前句柄"的规程叫规范归约（最右推导的逆过程）。

🗣️ 人话版：前面第 3 关你是"导演"，从 S 一路演到句子；这一关反过来——拿到一串单词，一步步"倒带"拼回 S。全篇核心问题其实只有一个：此刻栈顶这一坨，是已经凑齐句柄该缩了，还是还差几个字得继续移进？LR 分析就是回答这个问题的最强机器。后面所有概念（活前缀、项目、分析表）都是为"自动、正确地回答它"服务的。

核心难题：怎么在符号栈顶找出句柄（可归约串）？第5章的简单优先/算符优先分析适用面小（课程不讲，了解即可）；第6章 LR 分析是最一般、最强的解决方案——能识别几乎所有用无二义上下文无关文法描述的语言结构，是目前最一般的"移进-归约"方法，还能在扫描中及时发现错误并定位，且分析表可自动生成（YACC）。

LR(K) 名字含义：L = 从左到右扫描；R = 最右推导的逆（规范归约）；K = 向前看 K 个符号（省略时 K=1）

LR 分析器三件套（分析格局）：历史（栈里已移进/归约出的全部符号）+ 现实（当前输入符号）+ 展望（按产生式推测未来可能的输入）。动作只有四种：移进 s（单词进栈）、归约 r（栈顶句柄按规则 A→α 缩成 A）、接受 acc、报错。两根栈：状态栈 + 符号栈；一张表：ACTION（终结符列）+ GOTO（非终结符列）。

🥤比喻 · LR 总控 = 自动售货机（查表机器）：总控程序自己完全不思考，全部家当就是"两根栈 + 一张表 + 一个只看一个字的读头"。每步循环：读头瞄一眼当前字 → 拿「栈顶状态 + 当前字」去查 ACTION → 表说啥就干啥（移进/归约/acc/报错）。聪明全在提前算好的表里，总控蠢得像售货机——正因为蠢，才可靠、才能被 YACC 自动生成。
状态栈 0 2 ←栈顶　　符号栈 # a ←栈顶
输入串　b c d ▼读头只看这一个字 #　→ 查 ACTION[2,b]=s4 → 照办（b 进栈、压状态 4）→ 回到循环开头

🪜 2. 活前缀与可归前缀（LR 的钥匙）

🗣️ 人话版：活前缀就是一张"这半程没走错"的凭证——只要栈里攒的东西恰好是某个规范句型从头往后数、数到句柄已露出的部分为止的前缀，就说明你前面的移进/归约全干对了，放心继续；一旦栈里把整个句柄都攒齐（可归前缀），就是"该归约了"的信号。LR 分析器的一生，就是保证栈里永远是活前缀的一生。

  • 前缀：串的任意首部（abc 的前缀：ε,a,ab,abc）。
  • 活前缀（子前缀）：规范句型中不含句柄之后任何符号的前缀——即"句柄已露出的部分或句柄之前的部分"。一个活前缀可以是一个、也可以是若干（多个）规范句型的前缀。栈里只要是活前缀，就说明到目前为止的分析没走错。
  • 可归前缀：句柄之前包括句柄在内的串——句柄完整出现，该归约了！
🎬课件经典例：G: S→aAcBe, A→b|Ab, B→d，输入 abbcde。逐步归约时每次归约前栈中的内容（可归前缀）依次是 ab、aAb、aAcd、aAcBe。

拓广文法：给原文法加一条 S'→S。目的：让 S' 只出现在左部，归约出 S 时能分清"整个句子分析完成"还是"只是规则右部里出现的 S"——接受项目 S'→S· 唯一。

🏁终点线比喻 · 为什么非要加 S'→S：把"分析成功"想成马拉松冲线。原文法里 S 身兼两职——既是全程赛道（开始符号），又是赛道上的零件（如 S→aS 右部里就藏着一个 S）。于是每归约出一个 S，机器都会愣住：冲线了？还是只跑完一段？加 S'→S 等于在 S 外圈单独画一条终点线：S' 只在左部出现，所以 S'→S· 一亮，铁定是整场结束。用迷你文法 S→aS|b 跑输入 aab 感受一下：
时刻栈里【旁注】没有终点线会怎样
归约 b→S 后# a a S【旁注】出了个 S！但栈底还压着两个 a，它们是 S→aS 的半成品——此刻喊停就错了
归约 aS→S 后# a S【旁注】又是 S，还是零件。没有判据，机器永远不敢说"到站了"
最后一次归约# S【旁注】栈里只剩 S 且输入读完 ⇒ 唯一判据 S'→S· 点亮，acc！这行新规则就干了这一件事

📍 3. LR(0) 项目：给分析进度"拍快照"

🎯比喻：一条产生式就是一条任务清单，圆点 · 是"进度条光标"：S→a·AcBe 表示"a 干完了，正在等 A"。栈里每一步的进度快照组合 = 一个项目集；全部合法快照连成的状态图，就是识别活前缀的 DFA。

🗣️ 人话版：圆点的位置暴露你的意图——点后是终结符，你在"等原料到货"（移进项目）；点后是非终结符 B，你在"等分包商 B 交货"（待约项目）；点到尽头，这张卡干完了可以交活（归约项目）；而拓广文法那张卡干完，整个工程竣工（接受项目）。一个项目集 = 同一瞬间手里攥着的所有卡的进度合集。

LR(0) 项目与四大分类

在产生式右部加圆点：规则右部长度 n ⇒ n+1 个项目（A→ε 只有 A→·）。

类型形式含义/动作
移进项目A→α·aβ（点后是终结符）期待移进一个符号
待约项目A→α·Bβ（点后是非终结符）期待先归约出 B
归约项目A→α·（点在最后）句柄 α 已形成，按 A→α 归约
接受项目S'→S·（拓广文法专属）整个句子分析完毕，acc

两个函数构造项目集规范族

CLOSURE(I) 闭包：I 中项目全算上；若 A→α·Bβ ∈ I，则 B 的所有规则 B→·γ 都加进来；反复到不再扩大。
（直观：光标后面等着 B，就要把"开始干 B"的所有起点也摆上桌）
GO(I,X) = CLOSURE(J)，J = { A→αX·β | A→α·Xβ ∈ I }　（J 叫核：光标越过 X 的项目）

🗣️ 人话版：CLOSURE = "光标在等谁，就把谁的开工准备也摆上桌"；GO = "桌上所有光标后面是 X 的项目，光标统一右移一格，再补一轮闭包"。光说不练假把式，先用只有两条规则的迷你文法 G′: S'→S, S→aS | b 手算 I₀（【考点】大题第一步就从这开始）：

步进来的项目【旁注】它凭什么进来
0S'→·S【旁注】种子（即"核"）：I₀ 由它长出来
1S→·aS【旁注】上一步光标后是非终结符 S——得等 S 交货 ⇒ 把 S 的第①条规则的"开工版"摆上桌
2S→·b【旁注】同上，S 的第②条规则也一个不落地摆上
3（闭包完成）【旁注】新来的 S→·aS、S→·b 光标后是终结符，不牵扯任何人 ⇒ 停。I₀ = {S'→·S, S→·aS, S→·b}

再反复用 GO 长出全部状态（此文法共 5 个，每个状态配一句"此刻栈里发生了什么"）：

状态（怎么来的）项目集【旁注】此刻栈里发生了什么
I₀S'→·S, S→·aS, S→·b【旁注】开局，栈里只有 #，走 a、走 b、等 S 三种去向全有可能
I₁ = GO(I₀,S)S'→S·【旁注】栈里只剩一个完整 S ⇒ 冲线，acc
I₂ = GO(I₀,a)S→a·S, S→·aS, S→·b【旁注】刚移进一个 a，正等 S；后面再来 a（GO(I₂,a)=I₂ 自环）或 b（GO(I₂,b)=I₃）都行
I₃ = GO(I₀,b)S→b·【旁注】栈顶一个完整 b，句柄露全，立刻按 S→b 归约
I₄ = GO(I₂,S)S→aS·【旁注】栈顶凑齐 aS，按 S→aS 归约（弹掉 aS、压入 S，再查 GOTO 转状态）
DFA 一图流：I₀ ─S→ I₁(🏁acc)　｜　I₀ ─a→ I₂ ─a→ I₂（自环）　｜　I₀ / I₂ ─b→ I₃（归约）　｜　I₂ ─S→ I₄（归约）

构造流程：从 I₀=CLOSURE({S'→·S}) 出发，对每个状态、每个文法符号求 GO，产生新项目集就登记，直到没有新的——全体即 LR(0) 项目集规范族（识别活前缀的 DFA，初态 I₀，含归约项目/接受项目的状态是终态）。

📖 课件给过两种构造识别活前缀 DFA 的思路（了解思想）：① 构想一个 FA：把终结符/非终结符都当作输入符号，符号进栈 = 状态转换，识别出可归前缀即到达终态，这样先得到一个 NFA，再确定化；② 直接用 CLOSURE+GO 构造项目集规范族。二者殊途同归，第②种实用，第①种只是帮助理解"为什么项目集规范族就是识别活前缀的 DFA"。

⚖️ 4. SLR(1)：用 FOLLOW 调解冲突

🗣️ 人话版：LR(0) 是个"不抬头看路"的莽夫——状态里只要出现归约项目，就往整行所有列乱填 rⱼ；万一同一状态里还蹲着一个移进项目，两个动作就要抢同一个格子（冲突）。SLR(1) 的调解办法超省钱：让双方各亮管辖范围——移进方亮"点后面的终结符集合"，归约方亮"FOLLOW 集"，只要两边范围不重叠，就各管各的输入，井水不犯河水。

问题：一个项目集里同时有移进项目和归约项目（移进-归约冲突），或两个归约项目（归约-归约冲突）⇒ 不是 LR(0) 文法。

SLR(1) 调解规则：项目集 I 含移进项目（点后终结符 a₁…aₘ）和归约项目 B₁→α· … Bₙ→α·，若
{a₁,…,aₘ} 与各 FOLLOW(Bᵢ) 两两交集均为空，则面临输入 a 时：
① a=aᵢ ⇒ 移进　② a∈FOLLOW(Bᵢ) ⇒ 按 Bᵢ→α 归约　③ 否则报错

构造表时与 LR(0) 只差一条：归约项目 A→α· 只对 a∈FOLLOW(A) 的列填 rj（LR(0) 是无脑全列填）。

课件例：表达式文法 I₂ = {E→T·, T→T·*F}。FOLLOW(E)={#,+,)} 与 {*} 不相交 ⇒ 面临 #、+、) 时归约 E→T，面临 * 时移进。冲突解决，是 SLR(1) 文法！

步推理【旁注】这步在干嘛
①I₂ 同时含 E→T·（归约项目）与 T→T·*F（移进项目）【旁注】同一状态既想收工又想接着干 ⇒ 移进-归约冲突，LR(0) 表没法填
②移进方管辖 = { * }（点后只有 *）【旁注】只有下一符号是 * 时，才轮到移进派发言
③归约方管辖 = FOLLOW(E) = { #, +, ) }【旁注】按 E→T 归约出 E，只有"能合法跟在 E 后面"的符号才批准此刻动手
④{*} ∩ {#,+,)} = ∅【旁注】两派辖区完全错开 ⇒ 见 * 移进、见 #/+/) 归约，格子填得开了，冲突解除
⚠️SLR(1) 的软肋：FOLLOW 是"全局大杂烩"。反例：S→aAd|bAc|aec|bed, A→e 中 FOLLOW(A)={c,d}，项目集 {S→ae·c, A→e·}：面临 c 该移进，但 c∈FOLLOW(A) 又喊归约——冲突！为什么？因为 FOLLOW(A) 把所有句型里 A 后面的符号都算上了，而当前栈里是 ae，只有后跟 d 的情形才真正该归约。→ 需要按具体上下文给出更精确的跟班集合：LR(1)。

🔭 5. LR(1)：给每个项目配"望远镜"

🗣️ 人话版：SLR 打听的是"A 这个非终结符在全世界范围后面能跟啥"（FOLLOW，全局大杂烩）；LR(1) 改打听"A 在当前位置后面实际跟啥"——相当于给每个项目配一台专属望远镜（搜索符 a），只有下一输入恰好落进望远镜视野，才允许按这条规则归约。代价：同一个 LR(0) 项目会因所处位置不同被复制成好几份，状态数暴涨。

向前搜索符

LR(1) 项目 = [A→α·β, a]（二元式 = LR(0) 项目 + 向前搜索符 a）
含义：栈顶形成句柄 αβ 后，预期下一个输入恰是 a 时才用它归约。初始项目 [S'→·S, #]。
闭包规则：[A→α·Bβ, a] ∈ I ⇒ 对 b ∈ FIRST(βa) 加入 [B→·γ, b]（β 空则就是 FIRST(a)={a}）
GO 移点时搜索符不变
🧠直观理解：SLR 用"A 的全体跟班"（FOLLOW）判断归约；LR(1) 用"这个位置上 A 的跟班"（FIRST(βa)）——对非终结符的每次不同出现分别求后继，归约时机更精确，能消掉更多无效归约。

🔍 手算示范 · 搜索符到底怎么算出来的（【考点】必考计算）：用课件文法 S→BB, B→aB|b（拓广 S'→S）从初始项目求闭包，盯紧每步搜索符的来历：

步新项目【旁注】搜索符怎么算的
①[S'→·S, #]【旁注】初始项目，搜索符固定是 #（句末哨兵）
②[S→·BB, #]【旁注】①中点后是 S、β=ε ⇒ b ∈ FIRST(ε#)={#}：β 空，搜索符原样下传
③[B→·aB, a/b]、[B→·b, a/b]【旁注】②中点后是 B、βa = B# ⇒ FIRST(B#)=FIRST(B)={a,b}（B 推不出空，# 被挡住看不见）——这里的 B 只跟 a/b，不跟 #！

而分析走到 GO(I₀,B) 站（核 S→B·B,#，这已是第二个 B，后面直接是 #）时，闭包里 B 的项目搜索符就换成了 #：同一个 B，换个位置就换跟班——这就是 FIRST(βa) 的精髓，也是 LR(1) 比 SLR 精确的根源。

课件例（SLR 反例文法）：I₂ = {S→a·Ad, S→a·ec, A→·e, d}——此处 A 的搜索符只有 d（不含 c！），归约冲突消失。代价：搜索符不同会把同"心"的项目集分裂成多个，状态数可能成倍增长。

三法归约时机对比（必考）

方法何时执行归约 A→α·
LR(0)无论面临什么都归约（不看输入）
SLR(1)a ∈ FOLLOW(A) 时（全局跟班，偏乐观）

🗜️ 6. LALR(1)：合并同心，性价比之王

🗣️ 人话版：LR(1) 造出来的状态里，常有一堆"双胞胎班组"——手里的任务卡（心，即 LR(0) 部分）一模一样，只是胸前佩戴的搜索符（胸牌）不同。LALR(1) 说：活儿都一样，何必养两套班子？合并！胸牌取并集。状态数立刻缩回 LR(0)/SLR 的规模，能力只掉一点点——性价比之王，YACC 默认。

同心集：LR(0) 部分（心）相同、仅搜索符不同的 LR(1) 项目集。
LALR(1)：把同心集合并（心不变，搜索符取并集，转移函数自动合并）——状态数与 LR(0)/SLR 相同，能力介于 SLR(1) 与 LR(1) 之间
状态对共同的心搜索符差别【旁注】
I₃ 与 I₆B→a·B, B→·aB, B→·bI₃ 全带 a/b，I₆ 全带 #【旁注】I₃ 来自 I₀─a→（第一个 B 后面还跟 B），I₆ 来自 I₂─a→（第二个 B 后面就是 #）：位置不同跟班不同，任务卡却一字不差
I₄ 与 I₇B→b·I₄ 按 a/b 归约，I₇ 按 # 归约【旁注】合并成 I₄₇ 后，遇到 a/b/# 都按 B→b 归约——还是同一条规则，一条心不打架
I₈ 与 I₉B→aB·a/b 与 #【旁注】同理，合并后只是归约时机略放宽，仍是同一条规则
合并的本质心一动不动搜索符取并集【旁注】移进/待约看的是"心"里点后的符号，心没变 ⇒ 不可能新冒出移进-归约冲突；唯一风险：两个不同产生式的归约项目对新并来的搜索符同时点头 ⇒ 归约-归约冲突（下面课件例正是这么翻车的）
  • 合并同心集不会产生新的移进-归约冲突（移进看的是"心"里的点后符号，合并没变）；
  • 但可能产生新的归约-归约冲突：课件例 S→aAd|bBd|aBe|bAe, A→c, B→c——LR(1) 无冲突，合并后 A→c·,d/e 与 B→c·,d/e 撞车 ⇒ 该文法是 LR(1) 但不是 LALR(1)；
  • 合并后错误发现可能推迟（例：a*ba*b 语言，输入 ab#：LR(1) 3 步报错，LALR 5 步才报错——搜索符变宽，多做几次无效归约后才撞墙）。

🏆 7. 四种 LR 一张图记住

🗣️ 人话版：把四种方法想成同一台售货机的四个档位——LR(0) 不抬头看路（盲开，最容易撞车）；SLR(1) 出发前瞄一眼全局路况（FOLLOW）；LR(1) 每个路口都配专属向导（最聪明也最费内存）；LALR(1) 把双胞胎向导合并排班（省内存，YACC 默认档）。下面这张表就是四档说明书。

分析表特点文法条件
LR(0)最简单、局限大，是其余的基础项目集无任何冲突
SLR(1)简单实用、状态少冲突都能用 FOLLOW 解决
LR(1)能力最强、代价高（状态多）LR(1) 项目集无冲突
LALR(1)折衷：状态数同 SLR，能力介于中间，YACC 默认合并同心集后无新冲突
📏 判定顺序（简答题模板）：先构造 LR(0) 项目集规范族 → 无冲突 ⇒ 是 LR(0)（同时更是 SLR(1)、LALR(1)、LR(1)）→ 有冲突试 SLR(1) 方法 ⇒ 能解决即是 SLR(1)（更是 LALR(1)、LR(1)）→ 还不行构造 LR(1) 项目集族 ⇒ 无冲突是 LR(1)，再合并同心集 ⇒ 无新冲突则也是 LALR(1)。
能力关系：LR(0) ⊂ SLR(1) ⊂ LALR(1) ⊂ LR(1)（每个 SLR(1) 文法都是 LR(1) 文法，反之不一定）。
