🗺️ 1. 先看全景：编译器到底在干什么？

🎯一个比喻贯穿全课：编译器就像一位中翻英翻译家—— 你写的 C 语言是"汉语"（人好写），计算机只懂"英语"（机器指令）。把整篇文章先完整翻译完再交给对方读，就是编译； 请个口译坐旁边，你说一句他翻一句，就是解释。

三个必须分清的定义（考试常考）

  • 翻译程序：读入源程序，翻译成等价的另一种语言程序（目标程序）。上位概念。
  • 编译程序：源语言是高级语言（C、Java、Pascal），目标语言是低级语言（汇编 / 机器语言）。整体翻译完再执行。
  • 解释程序：对源程序边解释、边执行，不生成目标程序（Shell、JavaScript、SQL）。
编译 vs 解释的本质区别：是否生成目标代码
编译型（C/C++）解释型（Shell/JS/SQL）
是否生成目标程序生成不生成
错误发现时机编译时（一句错整个编译不过）运行时（一句错可跳过继续下一句）
执行效率高较低

🖱️ 点击下面的每个阶段，看它具体做什么（必考点）

👆 点一个阶段试试！比如"词法分析"。
🧠记忆主线：词法分析认单词 → 语法分析认句子 → 语义分析查含义 → 中间代码（四元式）→ 优化 → 目标代码。
前四个阶段 = 分析（拆解源程序），后两个阶段 = 综合（拼装目标程序）。全程有两根"电线"陪伴：表格管理（登记名字属性）与出错处理（语法错误在词法/语法阶段查，语义错误在语义分析阶段查）。

前端 / 后端 与"遍"

  • 编译前端：与源语言有关、与目标机无关（词法、语法、语义、中间代码）。编译后端：与源语言无关、依赖于中间代码、与目标机有关（优化、目标代码生成）。
  • 好处：前端相同、后端不同 → 同一语言编译到多种机器（X86/X64）；前端不同、后端相同 → 多种语言编译到同一中间语言。
  • 程序设计环境：编辑程序、连接程序、调试程序等工具与编译程序一起构成程序设计环境；把它们集成在一起就是 IDE（集成开发环境）。
  • 遍（趟 pass）：对源程序或中间结果从头到尾扫描一次并加工处理。PL/0 是单遍扫描的编译程序；分几遍由设计者权衡决定。
  • 编译程序结构 = 8 个框：词法、语法、语义分析程序 + 中间代码生成、代码优化、目标代码生成程序 + 表格管理程序 + 出错处理程序。

🔤 2. 文法：给语言立规矩（第2章）

🎯程序设计语言本质是一个记号系统。自然语言有"主谓宾"，程序语言也要有规矩——这套规矩的数学写法就是文法。第3~6章的所有算法都建立在它上面。

2.1 从符号到语言：一层层搭积木

  • 字母表 Σ：符号的非空有穷集合。如 {0,1}、{a,b,c}、ASCII 表。注意：元素不一定全是英文字母！
  • 符号串：字母表上符号组成的有穷序列。有序！ab ≠ ba。ε 是空串（长度0）。
❗ ε、∅、{ε} 三兄弟（经典考点）：ε 是一个空串（一个"内容为空"的串）；∅ 是空集合（里面连串都没有）；{ε} 是由空串组成的集合（有一个元素，这个元素是空串）。∅ 里没有元素，{ε} 里有一个元素！

🔬 符号串实验室（输入任何串，看它的"全家福"）

2.2 符号串的运算与闭包

  • 连接：xy = 把 y 接在 x 后面。x=ba, y=nana → xy=banana。
  • 方幂：x⁰=ε，x¹=x，x²=xx，xⁿ=xⁿ⁻¹x。x=ba → x³=bababa。
  • 字母表乘积：Σ₁Σ₂ = {ab | a∈Σ₁, b∈Σ₂}，不满足交换律。Σ⁰={ε}，Σⁿ=Σⁿ⁻¹Σ。
  • 正闭包 Σ⁺ = Σ∪Σ²∪Σ³∪…（长度≥1的所有串）；克林闭包 Σ* = Σ⁰∪Σ⁺（多了个 ε）。对符号串集合 U、V 同理有 UV、V*、V⁺。

2.3 文法的形式定义（四元组）

🗣️人话版：文法就是一本造句说明书。四元组 G=(VN,VT,P,S) 用大白话读：VN=半成品符号（还要继续替换的"词类"）、VT=成品符号（能写进最终句子的字）、P=替换规则手册、S=开工起点。
先玩个只有 1 条规则的玩具文法 G[S]: S→ab：从 S 出发，S ⇒ ab，一步造成一个句子——真实文法不过是规则更多、步数更多而已。
G = ( VN, VT, P, S )
成分含义要点
VN非终结符集语法成分（"词类"），如 E、A、S；非空有穷
VT终结符集能出现在最终句子里的符号；VT∩VN=∅
P规则(产生式)集α→β；左部 α∈(VT∪VN)⁺ 且至少含一个非终结符
S开始符号S∈VN，至少在左部出现一次

约定简写：只写产生式，如 G[E]: E→E+E | E*E | (E) | i（大写=非终结符，第一条规则左部=开始符号）。

📏 BNF 范式（元语言，可考）：用一套元符号描述文法——< > 括起语法单元（非终结符）、::= 表示"定义为"、| 表示"或"、{ } 表示重复 0 或多次、[ ] 表示可选（0 或 1 次）。例：<数字> ::= 0|1|2|…|9。PL/0 语言的语法定义用的就是 BNF 描述（教材 P13；PL/0 编译系统是本课程贯穿始终的示例语言）。

推导与归约（互为逆过程）

🗣️人话版：推导=照着规则手册造句，把大符号一步步换成小符号；归约=反方向验收，把小符号一步步收拢回大符号。一个自顶向下、一个自底向上，走的是同一条路的两个方向。
推导 ⬇ 造句： S ⇒ cAd ⇒ cabd   （大 → 小，自顶向下）
归约 ⬆ 验收： cabd ⇐ cAd ⇐ S   （小 → 大，自底向上）
αAβ ⇒ αγβ　（用了规则 A→γ，把串里的 A 换成 γ）
一步叫直接推导；多步记 ⇒⁺；允许一步也不走（α=β）记广义推导 ⇒*
  • 句型：S ⇒* α，α 可含非终结符（推导途中的半成品）
  • 句子：S ⇒* α 且 α ∈ VT*（全是终结符的成品）
  • 语言：L(G) = { α | α∈VT* 且 S ⇒* α }——所有句子的集合，L(G) ⊆ VT*
💡 文法的价值：用有限条规则描述无限的语言（当然 L(G) 也可以是有穷的）。

🎮 文法推导模拟器（亲手推一遍！）

文法 G[S]：S→cAd　A→ab|a（课件例）。目标：推出句子 cabd。
玩法：每一步点一条产生式按钮，程序会把最左边的非终结符替换掉，看你能推出目标串吗？

2.4 文法 ↔ 语言：互推经典四例（必背）

文法语言套路
S→bA, A→aA|aL = { baⁿ | n≥1 }A→aA|a 自复制出连续 a
S→AB, A→aA|a, B→bB|bL = { aᵐbⁿ | m,n≥1 }两段独立：A 管 a、B 管 b
S→aSb|abL = { aⁿbⁿ | n≥1 }两端同时长：递归要"配对"时用
S→aB|bB, B→a|bL = { aa,ab,ba,bb }有限语言直接枚举

反过来由语言写文法：L={abⁿa | n≥1} → S→aBa, B→bB|b。
⚠️ 一个文法唯一确定一个语言；但一个语言可对应多个等价文法（L(G1)=L(G2) 则 G1、G2 等价）。

2.5 乔姆斯基(Chomsky)四型文法（逐级收紧）

🗣️人话版：四型文法就像交规逐级收紧——0 型"想怎么开怎么开"，3 型"只能沿固定车道直行"。规矩越严，能描述的语言越少，但机器分析起来越省力。所以简单的活（认单词）交给最严的 3 型，复杂的活（认句子结构）才动用 2 型。判断题型时盯住产生式的"长相"：左部一整个非终结符=2 型；右部最多"一个终结符带个尾巴"=3 型。
类型别名产生式限制对应自动机（了解）
0型短语文法α→β，α 至少含一个非终结符图灵机
1型上下文有关|α| ≤ |β|（S→ε 可例外）线性界限自动机
2型上下文无关 CFGA→β（左部单个非终结符）下推自动机
3型正规文法(右线性)A→aB 或 A→a有限自动机
关系：3型 ⊂ 2型 ⊂ 1型 ⊂ 0型（限制越来越严）。语法分析用 2型；词法分析用 3型——第3、4、6章分别围绕它们展开。

2.6 语法树、最左/最右推导、二义性

🗣️人话版：二义性 = 同一个句子能画出两棵不一样的语法树，即"这句话有两种拆法"。就像中文"我看见了山上的人用望远镜"——到底谁拿着望远镜？两种理解都通。人可以靠语境猜，机器不能猜，所以含二义性的文法必须改造后才能用于编译。
  • 语法树：2型文法句型推导过程的图形表示，一棵树代表该句型所有可能的推导。
  • 最左推导：每步都替换最左非终结符；最右推导 = 规范推导（每步最右），与最左归约（规范归约）对应——LR 分析走的就是规范归约！
  • 二义性文法：存在某个句子对应两棵不同的语法树（等价说法：最左推导不唯一）。

✍️ 手算示范：i+i*i 的最左推导（一步一行）

步句型用哪条规则【旁注】
0E（起点）从开始符号出发，此刻只有一个可换的符号
1E+EE→E+E句子里有 +，选加法规则；句型里出现两个 E，规定先换最左那个——这就是"最左"推导
2i+EE→i最左的 E 直接换成 i（i 可看作标识符/数字）
3i+E*EE→E*E剩下的 E 造"先乘"的结构：对照树2，乘法在下层
4i+i*EE→i又是替换当前最左的非终结符
5i+i*iE→i全是终结符=句子，推导结束 ✅
⚠️经典例子：E→i | E+E | E*E | (E) 是二义的——句子 i+i*i 既能先算 +（树1）也能先算 *（树2）。消除方法见第4关（改写成 E→TE' 那套分层文法）。
树1：先算 (i+i)*i
树2：先算 i+(i*i)（符合优先级）

2.7 句型分析与"句柄"（第4/6章的地基）

判断一个串是否为句型，两条路：自顶向下（从 S 向下推导建树，难点：选哪条规则）；自底向上（从串向上归约到 S，难点：找可归约串）。

🧅人话版：自底向上归约像收拾桌子上的好几摞碗（好几 个直接短语）——规矩是每次只收最左边那一摞（句柄）。收走一摞，桌上可能又叠出新的一摞（归约出新非终结符），再找新的"最左一摞"继续收，直到桌面只剩一个大盘子 S。考试找句柄就是问：现在最左边能一把端走的那摞是啥？
设 αβδ 是句型，若 S ⇒* αAδ 且 A ⇒⁺ β：β 是 αβδ 的短语；若 A ⇒ β（一步）：β 是直接短语；最左直接短语 = 句柄
🧠形象理解：短语=树上某棵子树的全部叶子；直接短语=只有父子两层的子树叶子；句柄=最左边那棵"两层的子树"。自底向上分析每一步就归约当前句柄！

例：G[S]: S→cAd, A→ab|a，句型 cabd：短语 {cabd, ab}（整棵树和 A 子树的叶子串）、直接短语 {ab}、句柄 = ab。

2.8 实用约束：别写"坏"文法

  • 有害规则：U→U（自己推自己，除了引起二义毫无用处），禁止出现。
  • 多余规则：不可到达（从 S 出发永远用不到，如 B→b 但没有规则提到 B）或不可终止（永远推不出终结符串，如 D→Df），应删除。
